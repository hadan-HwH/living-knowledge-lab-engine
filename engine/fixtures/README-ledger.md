# `ledger/`가 뭔가 — 이름과 실제 (2026-08-05)

> **한 줄:** `ledger`(원장)는 **재생성할 수 없어서 보존해야 하는 것**이다.
> 세션 9의 fixture 재편(`fb19bac`, *"폴더가 역할을 말한다"*)이 정한 이름이다.

## 가른 기준

| 폴더 | 성격 | 지우면 |
|---|---|---|
| `canon/` | 정본 | **재생성 가능** — 원장에서 `regen.sh`로 다시 만든다 |
| `work/<app>/` | 회차 작업 | **재생성 가능** — 다시 추출하면 된다(비용은 든다) |
| `ledger/` | 보존 자산 | **복구 불가** |
| `bench/` | gold | 사람이 만든 정답 |

## 지금 `ledger/` 안에 있는 것 — 성격이 넷으로 갈린다

이름 하나에 성격이 다른 게 모여 있다. **정리는 미뤄뒀다** — 경로가 바뀔 때마다 배선이
조용히 끊긴 게 2026-08-04 감사에서 잡은 결함 3건(어휘 게이트 28/28 미실행 · 침식 감시
삼중 단절 · 최신성 오작동)의 원인이었다. **이름이 헐렁한 것보다 배선이 끊기는 게 비싸다.**

| 실제 성격 | 무엇 | 맞는 이름이라면 |
|---|---|---|
| **사람 판정** (복구 불가) | `*-adjudication.yaml` · `why/` · `VOCAB-ADJUDICATION.md` | **ledger** ✓ |
| **판정 대기 큐** (아직 판정 아님) | `VOCAB-QUEUE.yaml` | queue |
| **시점 보존** (기계 산출이나 되돌릴 근거) | `rounds/`(회차 정본) · `legacy/`(은퇴·구 계보) | archive |
| **기계 재생성 가능** | `decisions/`(결정층 이벤트 — `extract.py`가 다시 만든다) | work에 가까움 |

### 특히 헷갈리는 둘

- **`rounds/`** — 회차 정본의 사본이다. S6 `drift`가 "직전 회차 대비 무엇이 낡았나"를
  재는 `prev`로 쓴다. 성격상 `canon/rounds/`가 더 맞지만 배선(`previous_round`)이
  이 경로를 보고 있어 옮기지 않았다.
- **`legacy/`** — 둘이 섞여 있다. `<sha>.yaml` 묶음은 **구 계보 산출**이고,
  `retired-<앱>-<sha>.yaml`과 `retired-<앱>-<sha>/`는 **은퇴한 정본 슬라이스와 그 작업
  원장**이다(2026-08-05, 소유자 "예전 건 버려라"). 은퇴는 삭제가 아니라 이동이라 여기 있다.

## 규약

1. **`ledger/`에 있는 걸 기계가 덮어쓰지 않는다.** 사람 판정과 보존 자산이라서다.
   (`decisions/`만 예외 — `extract.py`가 원본에서 다시 만든다. 성격상 여기 있으면 안 되는데
   세션 9 재편 때 들어왔다.)
2. **은퇴는 정본 슬라이스와 작업 원장을 **둘 다** 옮긴다.** 정본만 빼면 재생 스윕이
   원장을 읽어 되살린다(실측: 여러 앱을 은퇴시킨 뒤 regen 한 번에 은퇴분이 전부 복귀했다).
3. **정리하려면 배선부터 세고 옮긴다.** 경로를 아는 곳은 `corpus.py` 한 곳으로 모아뒀다
   (`ledger_dir`·`canon_dir`·`work_dir`·`bench_dir`) — 옮길 때 거기만 고치면 되는지
   먼저 확인할 것.
